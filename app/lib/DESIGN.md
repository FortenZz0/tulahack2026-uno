# Архитектура Exoplanet Library

## Назначение

Библиотека получает данные NASA, преобразует их в объекты `Planet` и рассчитывает показатели потенциальной обитаемости экзопланет.

в разработке

## Компоненты

- `index.js` — публичные экспорты библиотеки.
- `exoplanet-library.js` — объект, через который внешний код управляет каталогом, загрузкой, состоянием и событиями.
- `nasa.js` — запросы к NASA Exoplanet Archive и преобразование данных.
- `planet.js` — модель данных `Planet`.
- `esi.js` — вычисление Earth Similarity Index (ESI).
- `habitable-zone.js` — расчёт зон обитаемости и (для планет с вытянутой орбитой) доли времени нахождения планеты в них.
- `tests/` — модульные тесты.

## Механика загрузки

1. Приложение вызывает `refresh()`.
2. Библиотека устанавливает статус `loading`.
3. `nasa.js` запрашивает данные из NASA.
4. При ошибке запрос повторяется до `maxAttempts` раз с экспоненциальной задержкой.
5. При успехе каталог заменяется новыми данными, статус становится `ready`, отправляется `updated`.
6. При окончательной ошибке статус становится `error`, отправляется `error`. Старый каталог сохраняется.

Параллельные вызовы `refresh()` объединяются в одну операцию.

## Модель данных

Каждая экзопланета представлена объектом `Planet`, содержащим:

- Название, массу, радиус, плотность, скорость убегания и равновесную температуру.
- Характеристики родительской звезды.
- Орбитальные параметры.
- Показатели ESI.
- Параметры зоны обитаемости и долю времени нахождения в ней.

Отсутствующие данные не заменяются дефолтными:
задача посчитать индексы хотя бы упрощенными, но научно-доказанными методами.

## Взаимодействие с клиентским кодом

Библиотека хранит полный каталог в памяти.

Клиент подписывается на события и самостоятельно получает данные через `getPlanets()`.

События не передают данные - если клиенту нужно среагировать на обновления, он должен сам запросить данные.
