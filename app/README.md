# Клиентское приложение

Точка входа — `app/main.js`, подключённая из `app/index.html` как ES module.
Здесь создаётся один `ExoplanetLibrary`, запускается загрузка каталога через
`GetPlanets(library)` и инициализируется звёздный фон через `createStarfield(starfieldOptions)`.
Остальные компоненты пока подключаются автоматически через `import.meta.glob`.
`app/lib` отвечает за работу с API; модуль списка — за отображение планет.

## Адаптивная компоновка

`sass/response.sass` подключается после стилей компонентов. От 992 px каталог
и область планеты стоят в две колонки; на невысоких экранах доступна прокрутка
страницы. До 991 px каталог получает ограниченную высоту с собственной
прокруткой, а модель и раскрытые характеристики идут ниже в потоке страницы.
До 575 px шапка переносится на две строки, отступы уменьшаются, основные
характеристики располагаются в две колонки. На сенсорном экране вертикальный
жест по модели прокручивает страницу, горизонтальный — вращает планету.

## Звёздный фон

Все настройки задаются в объекте `starfieldOptions` в `app/main.js`.
После изменения достаточно сохранить файл и обновить страницу.
Шейдер и управление отрисовкой находятся в `app/cmp/starfield/script.js`,
стили canvas и резервный градиент — в `app/cmp/starfield/style.sass`.

| Параметр | Значение | Допустимый диапазон и смысл |
| --- | --- | --- |
| `density` | `1` | `0…5`. Относительная плотность: `2` — примерно вдвое больше звёзд, `0` — без звёзд. Это количество на площадь экрана, не группировка в скопления. |
| `brightness` | `1` | `0…3`. Множитель яркости звёзд и их ореолов; дымку не меняет. |
| `twinkleFrequency` | `0.11` | `0…5` Гц. Базовая частота мерцания; у каждой звезды разброс ±25%. `0` останавливает мерцание. |
| `twinkleAmount` | `0.28` | `0…0.5`. Глубина мерцания: `0` — постоянная яркость, `0.5` — от полного затухания до максимума. |
| `driftSpeed` | `1` | `0…10`. Множитель скорости дрейфа. При `1` базовое движение ≈ 0,65 px/с по горизонтали и 0,25 px/с по вертикали, с разной скоростью трёх слоёв. `0` останавливает движение. |
| `starSize` | `1` | `0.25…3`. Множитель размера звёзд и ореолов. |
| `glow` | `0.13` | `0…1`. Интенсивность ореолов; `0` убирает их. |
| `nebulaIntensity` | `1` | `0…3`. Яркость цветной дымки; `0` оставляет тёмный фон. |
| `maxFps` | `30` | `1…60`. Верхний предел частоты кадров фона; фактическая частота зависит от экрана и нагрузки. |
| `maxPixelRatio` | `1.25` | `0.5…2`. Ограничение разрешения canvas относительно CSS-пикселей. Меньше — ниже нагрузка, больше — выше чёткость. |

При `prefers-reduced-motion: reduce` фон статичен. В скрытой вкладке отрисовка
приостанавливается. Без WebGL остаётся CSS-градиент. Настройки проверяются
при запуске; недопустимые значения вызывают `RangeError`.

`createStarfield()` возвращает объект с методом `dispose()`: он освобождает
WebGL-ресурсы, удаляет canvas и обработчики событий. При перезагрузке модуля
Vite его вызывает `main.js`, чтобы фон не запускался повторно поверх старого.

## Объяснение упрощённого ESI

Раздел `app/cmp/esi-explanation/` обновляется через `main.js` при выборе планеты.
Проверена фактическая [calculateSimpleESI в Worker](https://github.com/dfilirini/tulahack2026-uno-exoworker/blob/main/src/esi.js):
`dr = (R−1)/(R+1)`, `ds = (S−1)/(S+1)`, `ESI = 1−sqrt((dr²+ds²)/2)`.
Земные эталоны: 1 R⊕ и 1 S⊕. Шкалы показывают `1−abs(dr)` и `1−abs(ds)`:
это коэффициенты сходства от 0 до 1, а не процентные вклады в результат.
Итоговый ESI на клиенте не вычисляется — отображается только `planet.esi.simple`.

Место берётся из того же снимка топ-50, который показан в левом списке
(`library.getTopPlanets()`: ESI по убыванию, при равенстве — ID).
Земля по умолчанию остаётся эталоном без выдуманного серверного ESI или места.
Пропуски и пределы измерений показываются как «Недостаточно данных».
Радиус должен быть положительным, поток может быть нулевым, как в формуле Worker.
Плавное заполнение шкал отключается при `prefers-reduced-motion: reduce`.

## Материалы планет

`app/cmp/canvas/appearance.js` выбирает художественный пресет по готовому
`classification.sizeClass`. Размерную классификацию на клиенте не пересчитываем.

| Класс Worker | Условный материал |
| --- | --- |
| `MINI` | Серо-коричневая зернистая поверхность с большим числом кратеров |
| `terrestrial` | Минеральные оттенки, неоднородности и умеренный рельеф |
| `super-earth` | Более крупные пятна фактуры, каменистые палитры и небольшой рельеф |
| `sub-neptune` | Мягкий облачный узор, слабо выраженные полосы |
| `neptune` | Холодные палитры, широкие полосы и локальные вихревые пятна |
| `jupiter` | Контрастные охристые/кремовые полосы и вихревые пятна |
| `MEGA` | Крупные турбулентные полосы с отдельной палитрой |
| Неизвестный класс | Нейтральная серая фактура |

Опорные описания: [типы экзопланет NASA](https://science.nasa.gov/exoplanets/planet-types/),
[суперземли](https://science.nasa.gov/exoplanets/super-earth/),
[нептуноподобные планеты](https://science.nasa.gov/exoplanets/neptune-like/).
Это стилистические образы, а не выводы о реальном составе конкретной планеты.
Особенно `super-earth` обозначает размер, а не гарантированный каменистый состав.
Океаны, растительность и кольца автоматически не добавляются. Свечение — декоративное.
Земля сохраняет отдельный эталонный материал.

Нормализованное имя (NFKC, регистр, пробелы) хешируется FNV-1a в seed.
Детерминированный генератор задаёт палитру, шероховатость, масштаб шума,
кратеры и вихри. При отсутствии имени используется ID. Времени и `Math.random`
в генерации материалов экзопланет нет; шум эталонной Земли тоже детерминирован.
Пиксели создаются в `surface-pixels.js` на единичной сфере, без шва по долготе.
Повторный выбор и перезагрузка сохраняют внешний вид, пока не изменились имя,
класс или алгоритм. На GPU не накапливаются текстуры всего каталога.
